# FlowLang

A mini compiler for **FlowLang**, a small domain-specific language for event-driven
rules (smart-device automation, alerts, workflow rules). The compiler `flowc`
checks a `.flow` program for lexical, syntax and semantic errors, then translates
it into Python 3.

Compiler Design course project: *Design and Implementation of a Mini Compiler for
a Custom Programming Language*.

```
program SmartHome {
    let temperature: float = 32.5;

    event on_sensor_update {
        if temperature > 30.0 {
            emit "High temperature detected";
            call turn_on("fan");
        }
    }

    trigger on_sensor_update;
}
```

## How it works

```
 .flow source
     │
     ▼
 ┌─────────┐  tokens  ┌────────┐  AST  ┌──────────┐  annotated AST  ┌─────────┐
 │  Lexer  │ ───────▶ │ Parser │ ────▶ │ Semantic │ ──────┬───────▶ │ Codegen │ ──▶ .py
 └─────────┘          └────────┘       └──────────┘       │         └─────────┘
  lexical errors    syntax errors    semantic errors      │         ┌─────────┐
                                                          └───────▶ │   TAC   │ ──▶ three-address code
                                                                    └────┬────┘     (--tac, --quads)
                                                                         │ optional (--optimize)
                                                                    ┌────▼────┐
                                                                    │Optimiser│ ──▶ optimised TAC
                                                                    └─────────┘
```

Each phase only uses the output of the phase before it, and any error stops
compilation before Python is generated. The lexer and parser are **hand-written**
(recursive descent, LL(1)) instead of generated by tools like Flex/Bison, so every
part of the compiler is plain Python that can be read and explained.

Full language reference: [docs/language.md](docs/language.md)

## Roadmap

| Stage | What gets built | Compiler concepts | Status |
|---|---|---|---|
| 0 | Project setup, language spec, example programs | Phases of a compiler, front end vs back end, transpilers | ✅ Done |
| 1 | **Lexer**: source text → tokens, `--tokens` flag | Tokens, lexemes, finite automata, lexical errors | ✅ Done |
| 2 | **Parser**: tokens → AST, `--ast` flag | Grammars, recursive descent, LL(1), precedence, syntax errors | ✅ Done |
| 3 | **Semantic analysis**: symbol table, type checks, `--symbols` flag | Scopes, symbol tables, type systems, multi-pass analysis | ✅ Done |
| 4 | **Code generation**: AST → Python, `-o`, `--python` and `--run` flags | Tree walking, target code, runtime support | ✅ Done |
| 4½ | **Intermediate code**: three-address code, `--tac` and `--quads` flags | TAC, quadruples, temporaries, labels and jumps, short-circuit code | ✅ Done |
| 4¾ | **Optimisation** (optional): constant folding and propagation, dead code removal, `--optimize` flag | Basic blocks, optimisation passes, semantics-preserving transformations | ✅ Done |
| 5 | **Polish & review prep**: error messages, test suite, report, demo | Error reporting, testing a compiler | ⬜ |

## Project layout

```
flowlang/          the compiler (one module per phase, added stage by stage)
  main.py          command-line entry point (flowc)
  errors.py        error classes shared by all phases (line, column, caret display)
  tokens.py        token types, keyword table, Token class
  lexer.py         Stage 1: source text -> list of tokens
  ast_nodes.py     the node classes of the syntax tree (VarDecl, IfStmt, BinaryOp, ...)
  parser.py        Stage 2: list of tokens -> syntax tree (recursive descent)
  ast_printer.py   draws the syntax tree for --ast
  symbols.py       the symbol table: declared names in nested scopes
  semantic.py      Stage 3: checks names and types, annotates the tree with types
  codegen.py       Stage 4: annotated tree -> Python source code
  tac.py           Stage 4½: annotated tree -> three-address code (quadruples)
  optimizer.py     Stage 4¾: optional passes that simplify the three-address code
examples/          valid FlowLang programs
examples/errors/   programs that should fail, one error each
tests/             pytest tests, one file per phase
docs/
  language.md      language specification (lexical rules, grammar, semantics)
  learning-log.md  notes on what each stage taught
```

## Running

Requires Python 3.14. One-time setup:

```bash
python3 -m venv .venv && .venv/bin/python -m pip install -r requirements.txt
```

Compile a program (writes `build/smart_home.py`), or compile and run it:

```bash
.venv/bin/python -m flowlang examples/smart_home.flow
.venv/bin/python -m flowlang examples/smart_home.flow --run
```

Show the output of a single phase:

```bash
.venv/bin/python -m flowlang examples/smart_home.flow --tokens
.venv/bin/python -m flowlang examples/smart_home.flow --ast
.venv/bin/python -m flowlang examples/billing.flow --symbols
.venv/bin/python -m flowlang examples/billing.flow --tac
.venv/bin/python -m flowlang examples/billing.flow --quads
.venv/bin/python -m flowlang examples/security.flow --tac --optimize
.venv/bin/python -m flowlang examples/billing.flow --python
```

`playground.flow` is a scratch file for trying out FlowLang code.

Run the tests:

```bash
.venv/bin/python -m pytest
```
